## Tech design addendum

### D1: `user_id` path must not send `$top`/`$skiptoken` to `/users/{id}/joinedTeams`

- **Problem**: `graph_list_teams(user_id=...)` reuses the same `params` dict built for `GET /teams` (`$select`, `$top=min(page_size, 999)`, `$skiptoken` if `page_token` given) for `GET /users/{user_id}/joinedTeams`. Real Graph rejects `$top` on that endpoint with `invalid_argument` / "Query option 'Top' is not allowed" (comment #1600390000061290). Every `user_id` call fails, independent of `page_size`.
- **Fix**: when `user_id` is given, call `/users/{user_id}/joinedTeams` with only `$select` (no `$top`, no `$skiptoken`). Per the bug report this endpoint returns the user's full joined-teams list in one response (not paginated server-side) — consistent with the original design's Open Questions note that a single user's joined-teams list is "rarely multi-page in practice", now confirmed to mean Graph does not paginate this endpoint at all. Apply `page_size` and `name_prefix` filtering **client-side** on the full returned list; compute `has_more`/`next_page_token` from a client-side offset encoded into the same opaque `page_token` the caller already round-trips today, so the external contract (AC1's `has_more`/`next_page_token` pagination shape, unchanged) is identical for the caller on both branches — only the pagination mechanism differs internally (`$skiptoken` from Graph for `/teams`, a client-computed offset for `/users/{id}/joinedTeams`).
- **Still open, carried from the original Open Questions and sharpened here**: whether `$select` itself is accepted on `/users/{id}/joinedTeams` is unconfirmed without a live tenant call. If a real tenant rejects it too, drop `$select` for this one branch and return Graph's default field set (a one-line change). This does not block the fix — starting without `$select` on this branch is also an acceptable, more conservative default if the dev leg cannot confirm it against a real tenant.
- **Does not change**: the `name_prefix`-only and bare `/teams` calls (unaffected — already covered by TC-TEAMS-001/002/003/009); the response shape (`count`/`teams`/`has_more`/`next_page_token`); AC1, AC2, AC9. No new scope, no schema change, no cross-repo dependency.
- **Test gap to close** (not just the production code): the existing fake-`GraphClient` test helper does not reject unsupported query parameters for any path, so this class of bug (a real-Graph-only constraint) can recur silently for any tool. Fixing the fake client generally is out of scope for this ticket (a cross-cutting change affecting all 56 tools' tests); the regression case below (`TC-TEAMS-016`) instead asserts the *outgoing request shape* directly (no `$top`/`$skiptoken` in the recorded call), which catches this specific regression without needing the fake client itself to model Graph's per-endpoint parameter rules.
